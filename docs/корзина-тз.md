# ТЗ: корзина

Задание на реализацию. Написано после разбора кода 19 сентября 2026 года;
все упомянутые файлы, функции и соглашения существуют в репозитории на этот
момент. Перед началом прочитать `AGENTS.md` (там про Next 16) и `README.md`,
раздел «Устройство».

## Зачем

Удаление в проекте уже мягкое: `archiveNote` и `archiveFolder` ставят
`is_archived = true`, строки остаются в базе. Но восстановить их нельзя ни
через UI, ни через API, и архив никогда не чистится. Получается худшее из
двух: пользователь думает, что удалил навсегда, а место занято навечно.

Корзина закрывает обе стороны: удалённое можно вернуть, а через 30 дней оно
удаляется физически, вместе с файлами вложений на диске.

## Что должно получиться

1. Страница `/trash` со списком удалённого. У каждой строки: значок вида
   (папка или заметка), название, когда удалено, кнопки «Восстановить» и
   «Удалить навсегда». Сверху кнопка «Очистить корзину».
2. Ссылка «Корзина» в подвале боковой панели, рядом с «Карта связей».
3. После удаления из дерева тост «Заметка перемещена в корзину» с кнопкой
   «Восстановить». Диалог подтверждения удаления говорит про корзину, а не
   про безвозвратность.
4. Автоочистка: всё, что лежит в корзине дольше 30 дней, удаляется физически.
5. Интеграционные тесты в `tests/trash.test.ts`, один браузерный тест в
   `e2e/trash.spec.ts`, разделы в `README.md` и `docs/следующие-шаги.md`.

## Ключевое решение: `archived_at` вместо второго флага

Добавить в `folders` и `notes` колонку `archived_at timestamptz null`.
`is_archived` остаётся: на него завязаны partial-индексы, триггеры
`ensure_note_folder_owner_matches` и `ensure_folder_parent_owner_matches`
и два десятка запросов. Инвариант держит check-констрейнт:

```sql
check (is_archived = (archived_at is not null))
```

Колонка нужна для трёх вещей сразу:

- **Показать, когда удалено**, и посчитать срок автоочистки.
- **Отличить «удалено вместе с папкой» от «удалено раньше отдельно».** При
  архивировании поддерева все строки получают одно и то же `now()`: в
  Postgres оно фиксируется на транзакцию, а `archiveFolder` делает всё одним
  data-modifying CTE. Значит группа «что удалили одним действием» равна
  «одинаковый `archived_at` внутри поддерева». Отдельной таблицы или
  `deletion_id` не нужно.
- **Найти корни групп для списка корзины.** Корзина показывает не все
  архивные строки, а только вершины: удалённая папка с полусотней заметок
  внутри — одна строка, а не пятьдесят одна.

## Схема и миграция

В `src/db/schema.ts`:

- `folders.archivedAt`, `notes.archivedAt`: `timestamp({ withTimezone: true })`,
  nullable.
- Check-констрейнт выше на обеих таблицах (через `check()` из drizzle, как
  `folders_cannot_be_own_parent`).
- Partial-индекс для списка корзины и автоочистки на обеих таблицах:
  `(owner_id, archived_at) where is_archived = true`.

Миграция: `npm run db:generate`, затем дописать в `.sql` руками, как принято
в проекте (см. `drizzle/0004_attachments.sql`):

```sql
-- Backfill: всё, что уже архивировано, считаем удалённым в момент
-- последнего изменения. archiveNote и archiveFolder всегда обновляли
-- updated_at вместе с is_archived, других правок у архивных строк не было.
update notes   set archived_at = updated_at where is_archived and archived_at is null;
update folders set archived_at = updated_at where is_archived and archived_at is null;
```

Backfill обязан идти **до** добавления check-констрейнта, иначе он не
пройдёт. Если drizzle-kit сгенерирует констрейнт первым, переставить.

Переименовать файл миграции по образцу соседей: `0005_trash.sql`, тег в
`drizzle/meta/_journal.json` поправить соответственно.

Обновить `archiveNote` (`src/domain/notes.ts`) и `archiveFolder`
(`src/domain/folders.ts`): везде, где ставится `is_archived = true`, ставить
и `archived_at = now()`. В CTE у `archiveFolder` это одно `now()` на обе
ветки, ничего отдельно фиксировать не нужно.

## Доменный слой: `src/domain/trash.ts`

Все функции ищут строки по паре `(id, owner_id)`, как везде в проекте.
Ничего в этом файле не трогает неархивные строки, кроме restore.

### `listTrash(ownerId): Promise<TrashItem[]>`

```ts
interface TrashItem {
  kind: "folder" | "note";
  id: string;
  title: string;
  archivedAt: Date;
  /** Сколько заметок внутри, для папки. У заметки не заполняется. */
  noteCount?: number;
}
```

Возвращает **корни групп**, отсортированные по `archived_at desc`:

- Заметка входит в список, если она архивна и при этом либо `folder_id is
  null`, либо её папка не архивна, либо `folders.archived_at <>
  notes.archived_at`.
- Папка входит в список по тому же правилу относительно `parent_id`.
- `noteCount` для папки: число архивных заметок в её поддереве с тем же
  `archived_at`. Рекурсивный CTE; образец в `archiveFolder`.

Перед выборкой вызвать `purgeExpired(ownerId)` (см. ниже). Это единственное
место, где автоочистка запускается: проект уже живёт по принципу ленивых
производных (переиндексация векторов откладывается до ближайшего поиска),
и cron ему заводить незачем. Записать это в README честно: «очищается при
открытии корзины, не по расписанию».

### `restoreNote(ownerId, noteId): Promise<NoteView>`

- Найти архивную заметку владельца, иначе `notFound()`.
- Если `folder_id` указывает на архивную папку, заметка всплывает в корень:
  `folder_id = null`, позиция через `nextPosition(ownerId, null)` из
  `notes.ts` (функцию придётся экспортировать или продублировать).
  Триггер `notes_owner_matches_folder_owner` иначе упадёт с «Target folder
  does not exist or is archived», так что порядок именно такой: сначала
  решить про папку, потом снимать флаг одним `update`.
- Если папка живая, `folder_id` и `position` не трогать.
- `is_archived = false, archived_at = null, updated_at = now()`.
- Вернуть заметку через `noteColumns`.

### `restoreFolder(ownerId, folderId): Promise<Folder>`

- Найти архивную папку владельца, иначе `notFound()`.
- Взять её `archived_at` как метку группы.
- Одним data-modifying CTE в транзакции:
  1. Рекурсивно собрать поддерево, **отфильтровав по `archived_at =
     метка`** и на папках, и на заметках. Ветка, удалённая раньше отдельно,
     остаётся в корзине как свой собственный корень.
  2. Снять флаги с заметок группы.
  3. Снять флаги с папок группы.
  4. Если `parent_id` корневой папки указывает на архивную папку, корень
     всплывает в корень дерева: `parent_id = null`, позиция через
     `nextPosition` из `folders.ts`.
- Порядок в CTE важен из-за триггеров: триггер на `folders` срабатывает
  только `ON UPDATE OF parent_id, owner_id`, а на `notes` только
  `OF folder_id, owner_id`, поэтому снятие `is_archived` их не задевает.
  Единственный `update`, который их трогает, это `parent_id = null` у корня,
  а `null` триггер пропускает сразу.

### `purgeNote(ownerId, noteId): Promise<void>`

Физическое удаление одной заметки из корзины.

- Найти архивную заметку владельца, иначе `notFound()`.
- Прочитать её вложения (`id`, `mime_type`) **до** удаления строки.
- `delete from notes where ...`. Каскад уносит `attachments`, `note_links`,
  `note_chunks`.
- После успешного удаления строки удалить файлы через
  `deleteAttachmentFile` из `src/lib/uploads.ts`. Порядок «сначала база,
  потом диск» намеренный: осиротевший файл это занятое место, а строка без
  файла это сломанная картинка у того, кто заметку восстановит. Ошибку
  `unlink` функция уже глотает.

### `purgeFolder(ownerId, folderId): Promise<void>`

- Найти архивную папку владельца, иначе `notFound()`.
- Группа определяется так же, как в `restoreFolder`: поддерево с тем же
  `archived_at`.
- Прочитать вложения всех заметок группы до удаления.
- Дочерние папки **не из группы** (удалены раньше, отдельно) отцепить:
  `parent_id = null`. Иначе каскад `on delete cascade` у `folders.parent_id`
  унёс бы их вместе с родителем, хотя в корзине они лежат отдельной
  строкой. У заметок не из группы забота не нужна: у `notes.folder_id`
  стоит `on delete set null`, они сами станут корнями корзины.
- Удалить заметки группы, затем папки группы.
- Удалить файлы.

### `emptyTrash(ownerId): Promise<void>`

Всё архивное владельца: собрать вложения, удалить все архивные заметки,
затем все архивные папки, затем файлы. Групп здесь считать не нужно, каскад
за один раз выносит всё.

### `purgeExpired(ownerId): Promise<void>`

То же, что `emptyTrash`, но с условием `archived_at < now() - interval '30
days'`. Срок вынести константой `TRASH_RETENTION_DAYS = 30` в `trash.ts` и
показывать её на странице корзины: «Хранится 30 дней».

Тонкость: папка в группе могла попасть под срок, а заметка внутри нет
только если у них разный `archived_at`, то есть они из разных групп. Значит
удалять по сроку можно строки независимо, ничего не сломается: заметка с
`set null` всплывёт корнем корзины и дождётся своего срока.

## API

Два файла роутов, обвязка `authedJson` из `src/lib/api.ts`, id через
`parseResourceId`. Лимит по умолчанию (`RATE_LIMITS.mutation`), для `GET`
списка `RATE_LIMITS.publicRead`.

| Метод и путь | Что делает | Ответ |
| :-- | :-- | :-- |
| `GET /api/trash` | `listTrash` | `TrashItem[]` |
| `DELETE /api/trash` | `emptyTrash` | `{ ok: true }` |
| `POST /api/trash/notes/:id/restore` | `restoreNote` | `NoteView` |
| `POST /api/trash/folders/:id/restore` | `restoreFolder` | `Folder` |
| `DELETE /api/trash/notes/:id` | `purgeNote` | `{ ok: true }` |
| `DELETE /api/trash/folders/:id` | `purgeFolder` | `{ ok: true }` |

Структура файлов: `src/app/api/trash/route.ts`,
`src/app/api/trash/[kind]/[id]/route.ts` (DELETE),
`src/app/api/trash/[kind]/[id]/restore/route.ts` (POST). Сегмент `kind`
валидировать через `z.enum(["notes", "folders"])`, чужое значение это 404.

Существующие `DELETE /api/notes/:id` и `DELETE /api/folders/:id` не менять:
они и дальше кладут в корзину.

## Что не трогать

- Триггеры и их условие `is_archived = false` в целевых папках. Restore
  обходит их, поднимая строку в корень, а не ослабляя проверку.
- Публичные страницы и `getNoteForViewer`: архивная заметка отвечает 404
  и должна отвечать так же.
- Поиск, граф, связи: все запросы уже фильтруют `is_archived = false`,
  корзина в них не попадает. Проверить это тестом, а не менять код.
- Лимиты `notesPerUser` и `foldersPerUser`: считаются по живым строкам,
  корзина в них не входит. Оставить так.

   в корзине **две** строки, у них разный `archived_at`.
4. `restoreNote` возвращает заметку в живую папку с прежним `folder_id`.
5. `restoreNote` для заметки из архивной папки поднимает её в корень,
   `folder_id = null`, папка остаётся в корзине.
6. `restoreFolder` возвращает всё поддерево группы, а ветку с другим
   `archived_at` оставляет в корзине.

12. Check-констрейнт: прямой `update notes set is_archived = true` без
