# Деплой на свой сервер

Приложение и Postgres живут в docker compose, TLS и 80/443 держит системный
nginx. Postgres виден только внутри сети compose, приложение — только на
`127.0.0.1:3000` хоста, откуда его забирает nginx.

```
интернет ──443──> nginx (хост) ──> 127.0.0.1:3000 ──> app (контейнер)
                                                        └─> postgres (контейнер)
```

Команды даны для Debian/Ubuntu. Везде, где встречается `notes.example.com`,
подставьте свой домен.

## Что нужно до начала

- A-запись домена, указывающая на IP сервера (проверить: `dig +short notes.example.com`);
- sudo на сервере;
- 2 ГБ RAM или swap — сборка Next съедает 1.5–2 ГБ и на 1 ГБ падает с OOM (см. шаг 1);
- уже работающий nginx (`systemctl status nginx`).

---

## Шаг 1. Docker и swap

```bash
docker --version && docker compose version
```

Если Docker не стоит вообще:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"   # перелогиниться, чтобы группа применилась
```

Если движок есть, а вторая команда отвечает `unknown command: docker compose`
— это типично для пакета из архива Ubuntu, там compose идёт отдельным
пакетом. Сначала попробуйте apt:

```bash
apt-cache policy docker-compose-v2          # Candidate: (none) → пакета нет
sudo apt install -y docker-compose-v2
```

Если пакета нет, поставьте плагин бинарником — установленный движок это
не затронет:

```bash
ARCH=$(uname -m)   # x86_64 или aarch64
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL "https://github.com/docker/compose/releases/latest/download/docker-compose-linux-$ARCH" \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
docker compose version
```

Пакет `docker-compose` без `-v2` не подойдёт: это Python-обёртка версии 1.x,
она вызывается через дефис и не поддерживает `service_completed_successfully`,
на котором здесь держится порядок «сначала миграции, потом приложение».

Проверьте память:

```bash
free -h
```

Если суммарно (RAM + swap) меньше 2 ГБ, добавьте файл подкачки — иначе
`docker build` упадёт на `npm run build` без внятной ошибки, просто «Killed»:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## Шаг 2. Код на сервер

```bash
sudo mkdir -p /opt/md-note
sudo chown "$USER":"$USER" /opt/md-note
git clone <адрес-репозитория> /opt/md-note
cd /opt/md-note
```

Если репозиторий приватный и заводить на сервере ключ не хочется — залейте
с рабочей машины: `rsync -av --exclude node_modules --exclude .next ./ сервер:/opt/md-note/`.

## Шаг 3. OAuth-приложения

Callback URL везде вида `https://notes.example.com/api/auth/callback/<провайдер>`.
Достаточно одного провайдера, остальные можно не заполнять.

| Провайдер | Где завести | Провайдер в URL |
| :-- | :-- | :-- |
| GitHub | https://github.com/settings/developers | `github` |
| Яндекс | https://oauth.yandex.ru/client/new | `yandex` |
| VK ID | https://id.vk.com/about/business | `vk` |

## Шаг 4. Переменные окружения

```bash
cd /opt/md-note
cp .env.production.example .env.production
chmod 600 .env.production        # внутри пароль БД и секреты OAuth
nano .env.production
```

Что заполнить:

```bash
openssl rand -base64 24   # → POSTGRES_PASSWORD
openssl rand -base64 32   # → AUTH_SECRET
```

- `AUTH_URL` — `https://notes.example.com`, обязательно https и без слеша на конце.
- `DATABASE_URL` — тот же пароль, что и в `POSTGRES_PASSWORD`; хост здесь
  `postgres` (имя сервиса в compose), а не `localhost`.
- `ALLOWED_EMAILS` — **обязательно заполнить**. Если оставить пустым,
  зарегистрироваться сможет любой, кто нашёл сайт.

## Шаг 5. Поднять приложение

```bash
cd /opt/md-note
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Первая сборка — несколько минут. Compose поднимет Postgres, дождётся его
готовности, прогонит миграции одноразовым контейнером и только после его
успешного выхода запустит приложение.

Проверка:

```bash
docker compose -f docker-compose.prod.yml ps          # app и postgres — Up
curl -I http://127.0.0.1:3000                         # ожидаем 200 или 307
ss -tlnp | grep 3000                                  # слушает 127.0.0.1, не 0.0.0.0
```

Последняя проверка важна: если в выводе `0.0.0.0:3000`, приложение открыто в
интернет мимо nginx и мимо ufw.

## Шаг 6. nginx

```bash
cd /opt/md-note
sudo cp deploy/md-note.nginx.conf /etc/nginx/sites-available/md-note
sudo sed -i 's/notes\.example\.com/СВОЙ.ДОМЕН/g' /etc/nginx/sites-available/md-note
sudo ln -s /etc/nginx/sites-available/md-note /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Если `nginx -t` ругается на конфликт `server_name` — значит домен уже описан
в другом файле в `sites-enabled` (часто это `default`). Уберите дубль.

Теперь сайт должен открываться по http:

```bash
curl -I http://notes.example.com
```

## Шаг 7. Сертификат

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d notes.example.com
```

Certbot сам допишет в конфиг `listen 443 ssl`, пути к сертификату и редирект
с http на https. Автопродление ставится вместе с пакетом, проверить:

```bash
sudo certbot renew --dry-run
```

## Шаг 8. Файрвол

```bash
sudo ufw allow 'Nginx Full'
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status
```

Порты 3000 и 5432 открывать не нужно и нельзя.

## Шаг 9. Первый вход

Откройте `https://notes.example.com`, войдите через OAuth.

Если ваш email есть в `ALLOWED_EMAILS`, доступ выдастся сразу. Иначе попадёте
на `/pending` — одобрить руками:

```bash
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U mdnote -d mdnote -c "update users set is_approved = true where email = 'вы@example.com';"
```

## Шаг 10. Бэкапы

```bash
crontab -e
```

```
0 4 * * * /opt/md-note/scripts/backup.sh >> /var/log/md-note-backup.log 2>&1
```

Дампы лягут в `/opt/md-note/backups`, копии старше 14 дней удаляются.
Через сутки проверьте, что файл появился, — и хотя бы раз прогоните
восстановление на тестовой базе, непроверенный бэкап бэкапом не считается.

Восстановление:

```bash
gunzip -c backups/md-note-2026-08-26-0400.sql.gz | \
  docker compose -f docker-compose.prod.yml exec -T postgres psql -U mdnote -d mdnote
```

Сам файл `.env.production` в дамп не входит — сохраните его отдельно, без
`AUTH_SECRET` все текущие сессии умрут, а без пароля БД дамп не развернуть.

## Обновление

```bash
cd /opt/md-note
git pull
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Миграции применяются автоматически при каждом `up`. Даунтайм — время сборки
плюс несколько секунд на перезапуск контейнера.

## Полезные команды

| Команда | Что делает |
| :-- | :-- |
| `docker compose -f docker-compose.prod.yml logs -f app` | логи приложения |
| `docker compose -f docker-compose.prod.yml logs migrate` | что сделали миграции |
| `docker compose -f docker-compose.prod.yml restart app` | перезапуск без пересборки |
| `docker compose -f docker-compose.prod.yml exec postgres psql -U mdnote -d mdnote` | psql |
| `sudo tail -f /var/log/nginx/error.log` | ошибки прокси |

## Если что-то не работает

**502 Bad Gateway.** Контейнер приложения не поднялся или упал. Смотрите
`logs app`; частая причина — опечатка в `DATABASE_URL`.

**После входа редиректит на `http://localhost:3000`.** До приложения не
доходят `X-Forwarded-Proto` / `X-Forwarded-Host`. Проверьте, что в
`sites-available/md-note` эти два `proxy_set_header` на месте — certbot при
переписывании конфига location не трогает, но если конфиг правили руками,
их легко потерять.

**`redirect_uri_mismatch` у провайдера.** `AUTH_URL` в `.env.production` не
совпадает с callback URL в настройках OAuth-приложения. После правки
`.env.production` нужен `up -d`, простого `restart` мало — переменные
подставляются на старте compose.

**Всех кидает на `/pending`.** Пустой или неверный `ALLOWED_EMAILS`. Учтите,
что VK не отдаёт email, а у GitHub он может быть скрыт настройками приватности
— тогда в базе `users.email` будет `null` и список не сработает; одобряйте по
`id` через psql.

**`Killed` во время сборки.** Не хватило памяти. Добавьте swap (шаг 1) или
соберите образ на рабочей машине и отправьте на сервер:
`docker save md-note-app | ssh сервер 'docker load'`.
