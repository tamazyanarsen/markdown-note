# давай итоговый вариант с описанием БД и поведением

особенно, важно про перемещение
будем проверять, что является владельцем и заметки, и папки

Ниже итоговая модель для MVP: личное дерево заметок, постоянные UUID-ссылки, у заметок только `private | public`, а ссылка на папку всегда доступна внешнему пользователю и показывает только публичную часть дерева.

## Инварианты и поведение

### Ресурсы

Есть два вида ресурсов:

- **Folder** — папка, может содержать другие папки и заметки.
- **Note** — заметка, содержит текстовый документ и имеет видимость `private` или `public`.

У обоих ресурсов есть `id UUID`. Это одновременно:

- первичный ключ в БД;
- неизменяемый идентификатор ресурса;
- идентификатор в ссылке.

```text
/f/:folderId
/n/:noteId
```

Пример:

```text
/f/7f4ffbf1-8569-4c14-ba1d-233937a61d75
/n/ca3451c1-6234-468e-94a4-8ca841c1e48b
```

UUID — встроенный тип PostgreSQL; он подходит для глобально уникальных идентификаторов и не требует отдельного `publicId`.[^1]

### Владение

Каждая папка и заметка имеет одного владельца:

```text
folders.owner_id → users.id
notes.owner_id   → users.id
```

В MVP нет ACL, invitations, командных workspaces и общего редактирования.

**Инвариант дерева:** заметку можно положить только в папку того же владельца.

```text
note.owner_id = targetFolder.owner_id
```

Аналогично папку можно вложить только в папку того же владельца:

```text
movingFolder.owner_id = targetFolder.owner_id
```

Это делает модель доступа простой и предсказуемой: пользователь видит и изменяет только своё дерево.

### Доступ к заметке

| Запрос | Public-заметка | Private-заметка |
| :-- | :-- | :-- |
| Гость открывает `/n/:id` | Получает заметку | Получает `404` |
| Владелец открывает `/n/:id` после авторизации | Получает заметку | Получает заметку |
| Другой авторизованный пользователь | Получает заметку | Получает `404` |

UUID в URL — идентификатор, а не секретный access-token. Знание UUID не открывает private-заметку.

### Доступ к папке

Ссылка на папку существует и открывается для любого пользователя:

```text
GET /f/:folderId
```

Поведение зависит от того, является ли вызывающий пользователь владельцем.


| Кто открывает папку | Что получает |
| :-- | :-- |
| Владелец | Полное поддерево: все вложенные папки, public- и private-заметки |
| Гость | Только public-заметки и папки, ведущие к ним |
| Другой авторизованный пользователь | То же, что гость |

Private-заметка вообще не попадает в публичный API-ответ: не передаются её UUID, заголовок, `visibility`, время изменения и позиция.

Папка без public-заметок открывается, но для гостя выглядит пустой:

```json
{
  "id": "7f4ffbf1-8569-4c14-ba1d-233937a61d75",
  "title": "Личные финансы",
  "children": []
}
```


### Вложенные папки

Гость видит только «публичный скелет» дерева: корневую папку по ссылке и все папки на путях к хотя бы одной public-заметке.

Полное дерево владельца:

```text
Проекты
├── Архитектура
│   ├── ADR: доступы                      public
│   └── Черновик миграции                 private
├── Финансы
│   └── План расходов                     private
└── Идеи
    └── Заметки о продукте                public
```

Гость, открывший `/f/:проекты`, увидит:

```text
Проекты
├── Архитектура
│   └── ADR: доступы
└── Идеи
    └── Заметки о продукте
```

Папка `Финансы` и private-заметка «Черновик миграции» не существуют для него на уровне ответа API.

## Схема БД

```sql
create extension if not exists pgcrypto;

create type note_visibility as enum ('private', 'public');

create table users (
  id uuid primary key default gen_random_uuid(),

  email citext not null unique,
  display_name text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table folders (
  id uuid primary key default gen_random_uuid(),

  owner_id uuid not null
    references users(id) on delete cascade,

  parent_id uuid null
    references folders(id) on delete cascade,

  title text not null,

  -- Общая сортировка папок среди дочерних папок.
  position numeric(20, 10) not null default 1000,

  is_archived boolean not null default false,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint folders_cannot_be_own_parent
    check (id <> parent_id)
);

create table notes (
  id uuid primary key default gen_random_uuid(),

  owner_id uuid not null
    references users(id) on delete cascade,

  folder_id uuid null
    references folders(id) on delete set null,

  title text not null,

  visibility note_visibility not null default 'private',

  -- Например, структурированный документ Tiptap / Lexical / ProseMirror.
  content jsonb not null default '{"type":"doc","content":[]}'::jsonb,

  -- Для поиска и preview; заполняется приложением при сохранении content.
  plain_text text not null default '',

  -- Общая сортировка заметок внутри папки.
  position numeric(20, 10) not null default 1000,

  is_archived boolean not null default false,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

`id` — единственный UUID, который используется и внутри системы, и в URL. Первичный ключ автоматически получает индекс, поэтому отдельные индексы по `id` не нужны. PostgreSQL нативно поддерживает UUID и функции его генерации.[^2][^1]

### Индексы

```sql
create index folders_parent_position_idx
  on folders(parent_id, position)
  where is_archived = false;

create index folders_owner_parent_position_idx
  on folders(owner_id, parent_id, position)
  where is_archived = false;

create index notes_folder_position_idx
  on notes(folder_id, position)
  where is_archived = false;

create index notes_public_folder_position_idx
  on notes(folder_id, position)
  where visibility = 'public'
    and is_archived = false;

create index notes_owner_idx
  on notes(owner_id)
  where is_archived = false;
```


### Важное ограничение сортировки

В текущей схеме `folders.position` и `notes.position` сортируются независимо. Это означает:

```text
Папки: position = 100, 200
Заметки: position = 100, 200
```

Если в интерфейсе нужен единый drag-and-drop порядок, где папки и заметки перемешаны, лучше добавить общую таблицу размещения.

Для первого MVP можно принять простое правило:

```text
Сначала папки, затем заметки.
```

Если нужен произвольный единый порядок с самого начала, лучше сразу использовать единую таблицу `nodes`. Но для выбранной раздельной модели достаточно отображать:

```sql
select 'folder' as kind, id, title, position
from folders
where parent_id = $folder_id

union all

select 'note' as kind, id, title, position
from notes
where folder_id = $folder_id

order by position;
```

Тогда `position` работает как общий ключ сортировки для обеих выборок.

## Перемещение

Перемещение — критичный use case, потому что оно меняет структуру дерева и может случайно смешать данные разных владельцев.

Все операции выполняются **в одной SQL-транзакции**. Нельзя доверять только фронтенду: проверки должны быть в application service и, по возможности, продублированы триггерами БД.

### Перемещение заметки

Запрос:

```text
POST /api/notes/:noteId/move
{
  "targetFolderId": "uuid | null",
  "position": 250
}
```

`targetFolderId = null` означает перемещение в корень личного дерева пользователя.

Правила:

1. Пользователь должен быть авторизован.
2. Он должен быть владельцем заметки:

```text
note.owner_id = actor.user_id
```

3. Если `targetFolderId` задан, пользователь должен быть владельцем целевой папки:

```text
target_folder.owner_id = actor.user_id
```

4. Владелец заметки и папки должен совпадать:

```text
note.owner_id = target_folder.owner_id
```

5. Обновляются только `folder_id`, `position`, `updated_at`.
6. `visibility` при перемещении **не меняется**: private остаётся private, public остаётся public.
```sql
begin;

select id, owner_id
from notes
where id = $note_id
  and is_archived = false
for update;

select id, owner_id
from folders
where id = $target_folder_id
  and is_archived = false
for update;

-- Проверки owner_id выполняет application service.

update notes
set
  folder_id = $target_folder_id,
  position = $position,
  updated_at = now()
where id = $note_id;

commit;
```

Если целевая папка не передана, проверяется только ownership заметки, затем устанавливается `folder_id = null`.

### Перемещение папки

Запрос:

```text
POST /api/folders/:folderId/move
{
  "targetFolderId": "uuid | null",
  "position": 250
}
```

Правила:

1. Пользователь владеет перемещаемой папкой.
2. Если задана целевая папка, пользователь владеет и ей.
3. Владельцы исходной и целевой папки совпадают.
4. Нельзя переместить папку в саму себя.
5. Нельзя переместить папку в любую из её дочерних папок.
6. Если `targetFolderId = null`, папка становится корневой.
7. При переносе папки все вложенные папки и заметки остаются на месте относительно неё: меняется только `parent_id` самой переносимой папки.

Проверка «целевая папка — потомок перемещаемой» через recursive CTE:

```sql
with recursive subtree as (
  select
    id,
    parent_id,
    array[id] as path
  from folders
  where id = $moving_folder_id

  union all

  select
    child.id,
    child.parent_id,
    subtree.path || child.id
  from folders child
  join subtree on child.parent_id = subtree.id
  where child.is_archived = false
    and not child.id = any(subtree.path)
)
select exists (
  select 1
  from subtree
  where id = $target_folder_id
) as target_is_descendant;
```

Если `target_is_descendant = true`, операция завершается ошибкой `409 Conflict`:

```json
{
  "code": "FOLDER_MOVE_CYCLE",
  "message": "Нельзя переместить папку внутрь самой себя или её потомка."
}
```

Рекурсивные CTE подходят для обхода иерархий. PostgreSQL отдельно рекомендует контролировать завершение рекурсии и предлагает отслеживать уже посещённые узлы для защиты от циклов.[^3]

### Триггер: заметка только в папке владельца

Проверка в application service обязательна. Триггер дополнительно предотвращает нарушение инварианта при прямом SQL, миграции или будущем сервисе.

```sql
create or replace function ensure_note_folder_owner_matches()
returns trigger
language plpgsql
as $$
declare
  target_folder_owner_id uuid;
begin
  if new.folder_id is null then
    return new;
  end if;

  select owner_id
  into target_folder_owner_id
  from folders
  where id = new.folder_id
    and is_archived = false;

  if target_folder_owner_id is null then
    raise exception 'Target folder does not exist or is archived';
  end if;

  if new.owner_id <> target_folder_owner_id then
    raise exception
      'A note can only be placed in a folder of the same owner';
  end if;

  return new;
end;
$$;

create trigger notes_owner_matches_folder_owner
before insert or update of folder_id, owner_id
on notes
for each row
execute function ensure_note_folder_owner_matches();
```


### Триггер: папка только в папке владельца

```sql
create or replace function ensure_folder_parent_owner_matches()
returns trigger
language plpgsql
as $$
declare
  target_parent_owner_id uuid;
begin
  if new.parent_id is null then
    return new;
  end if;

  select owner_id
  into target_parent_owner_id
  from folders
  where id = new.parent_id
    and is_archived = false;

  if target_parent_owner_id is null then
    raise exception 'Target parent folder does not exist or is archived';
  end if;

  if new.owner_id <> target_parent_owner_id then
    raise exception
      'A folder can only be placed in a folder of the same owner';
  end if;

  return new;
end;
$$;

create trigger folders_owner_matches_parent_owner
before insert or update of parent_id, owner_id
on folders
for each row
execute function ensure_folder_parent_owner_matches();
```

Триггер не должен быть единственной защитой от циклов: для этого лучше отдельная проверка в use case перемещения папки, потому что нужно вернуть пользователю понятную доменную ошибку.

## Публичное дерево папки

Для `GET /f/:folderId` сервер сначала находит папку. Если она существует и не архивна:

- владелец получает полное дерево;
- остальные получают только public-проекцию.

Алгоритм публичной проекции:

1. Рекурсивно получить все вложенные папки, начиная с корня по ссылке.
2. Выбрать только неархивные заметки с `visibility = 'public'`.
3. Оставить корневую папку и папки-предки этих заметок.
4. Удалить все ветви, в которых нет доступной public-заметки.
5. Не передавать сведения о private-заметках.
```sql
with recursive folder_tree as (
  select
    f.id,
    f.parent_id,
    f.title,
    f.position,
    array[f.id] as path
  from folders f
  where f.id = $folder_id
    and f.is_archived = false

  union all

  select
    child.id,
    child.parent_id,
    child.title,
    child.position,
    ft.path || child.id
  from folders child
  join folder_tree ft on child.parent_id = ft.id
  where child.is_archived = false
    and not child.id = any(ft.path)
),
public_notes as (
  select
    n.id,
    n.folder_id,
    n.title,
    n.position,
    n.updated_at
  from notes n
  join folder_tree ft on ft.id = n.folder_id
  where n.is_archived = false
    and n.visibility = 'public'
),
visible_folder_ids as (
  -- Корень всегда виден, даже если в нём нет public-контента.
  select $folder_id::uuid as folder_id

  union

  -- Для каждой public-заметки показываем все папки на пути к ней.
  select distinct unnest(ft.path) as folder_id
  from folder_tree ft
  join public_notes pn on pn.folder_id = ft.id
)
select
  f.id,
  f.parent_id,
  f.title,
  f.position,
  'folder' as kind,
  null::uuid as folder_id_for_note,
  null::timestamptz as updated_at
from folder_tree f
join visible_folder_ids v on v.folder_id = f.id

union all

select
  n.id,
  n.folder_id as parent_id,
  n.title,
  n.position,
  'note' as kind,
  n.folder_id as folder_id_for_note,
  n.updated_at
from public_notes n

order by parent_id nulls first, position, kind;
```

Для заметок в корне пользователя (`folder_id is null`) публичная ссылка на папку их не показывает — это ожидаемо: они не входят в поддерево конкретной папки.

### Ошибки

| Ситуация | HTTP-статус | Код |
| :-- | --: | :-- |
| Неверный UUID | 404 | `NOT_FOUND` |
| Ресурс не существует или архивирован | 404 | `NOT_FOUND` |
| Гость открывает private-заметку | 404 | `NOT_FOUND` |
| Не владелец меняет ресурс | 403 | `FORBIDDEN` |
| Заметка переносится в чужую папку | 403 | `OWNER_MISMATCH` |
| Папка переносится в чужую папку | 403 | `OWNER_MISMATCH` |
| Папка переносится в себя/потомка | 409 | `FOLDER_MOVE_CYCLE` |
| Целевая папка не найдена | 404 | `TARGET_FOLDER_NOT_FOUND` |

## Решения для MVP

- PostgreSQL.
- Раздельные `folders` и `notes`.
- UUID `id` — одновременно primary key и URL-ID.
- У заметок только `private | public`.
- У папок нет собственного visibility.
- Папка по ссылке всегда доступна; гость видит только публичное поддерево.
- Private-заметки не раскрываются в публичном ответе.
- Изменять и перемещать ресурсы может только владелец.
- Перемещение возможно исключительно между папками того же владельца.
- Для папок обязательна защита от циклов.
- Все move-операции — в транзакции с блокировкой изменяемых ресурсов.
