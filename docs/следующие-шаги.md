# Следующие шаги

Состояние на 5 сентября 2026 года. Файл нужен, чтобы через месяц не
восстанавливать контекст по памяти: что сделано, что проверено, что осталось
и почему принимались решения.

Доменная модель — [`описание.md`](описание.md). Устройство проекта и команды —
[`../README.md`](../README.md). Механизм поиска целиком — [`поиск.md`](поиск.md).

## Где мы сейчас

MVP собран целиком и работает локально. Реализованы все восемь этапов плана:
каркас, схема БД с триггерами, авторизация, CRUD дерева, редактор markdown,
публичные страницы, перемещение с drag & drop, сборка и деплой в Docker.

Поверх MVP добавлены четыре вещи: похожие заметки, wiki-ссылки с обратными
ссылками, вложения и вопрос-ответ по заметкам. Все четыре описаны в README,
каждая деградирует до «просто не работает», если внешний API недоступен
или не настроен.

### Что нашли браузерные тесты

Три штуки, все чинились в коде, а не в тестах:

1. **`closeBrackets` дописывал `]]`.** Набранное `[[` превращалось редактором
   в `[[]]`, и подстановка оставляла в тексте хвост `[Заголовок](/n/…)]]`.
   Теперь `apply` съедает дописанные скобки (`src/components/note/wiki-link.ts`).
2. **Причина отказа загрузки не доходила до человека.** `validationError`
   кладёт подробности в `details`, а клиент показывает `message` — на попытку
   вставить svg выпадало «Некорректные данные запроса». Появился
   `uploadRejected` с конкретным текстом.
3. **Гонка при переиндексации.** Поиск и панель связей запускают её
   одновременно, `delete` одного попадал между `delete` и `insert` другого —
   `duplicate key` на `note_chunks`. Плюс заметка могла исчезнуть, пока
   считались векторы, и вставка падала по внешнему ключу. Оба случая закрыты
   блокировкой строки заметки в `replaceNoteChunks`.

### Что НЕ проверено

- **VK ID** — единственный непроверенный код в проекте. Встроенный провайдер
  Auth.js ходит в устаревший `oauth.vk.com`, поэтому в
  `src/lib/auth/vk-id.ts` написан свой под актуальный VK ID с PKCE и
  пробросом `device_id` через `AsyncLocalStorage`. Проверить нельзя было
  физически: VK не принимает `localhost` в Redirect URI.
- **GitHub** — проверена только сборка редиректа (хост, `client_id`,
  `redirect_uri`, скоупы, PKCE). Полный круг «клик → callback → сессия» не
  проходили: логинились Яндексом.
- **Палитра в браузере.** Весь путь проверен через HTTP: кнопка «Поиск» и
  `Ctrl K` рендерятся в шапке, эндпоинт отвечает 401 гостю и не редиректит
  на `/signin`, выдача правильная. Но клика по `Ctrl+K` живым человеком ещё
  не было — расширение браузера до сессии не достучалось. Непроверенным
  остаётся только клиентский слой: перехват сочетания клавиш, две паузы
  (120 мс и 400 мс) и навигация стрелками в cmdk.
- **Отсечка `MAX_SEMANTIC_DISTANCE` = 0,65** измерена на трёх заметках и
  шести запросах. Разделение было чистым (0,38–0,55 против 0,67–0,75), но
  выборка маленькая. Если на выросшей базе полезная заметка перестанет
  находиться — смотреть сюда в первую очередь.
- **Перетаскивание файла в редактор.** Вставка из буфера покрыта браузерным
  тестом, drop — нет: у него отдельная ветка с `posAtCoords`, и позиция
  вставки там считается иначе. Проверить мышью.
- **Загрузка через настоящий nginx.** `client_max_body_size` поднят до 12m
  в `deploy/md-note-proxy.conf`, но десятимегабайтный файл через прокси
  никто не гонял.
- **Мобильная раскладка новых блоков.** Панель связей и режим ответа
  проверены только на десктопном разрешении.

## Ближайшие шаги

### 1. Мелочи, ничего не блокируют

- [ ] Удалить тестового пользователя `test@example.com` вместе с деревом из
      примера документа — он не виден вашему аккаунту, но лежит в базе:
      `delete from users where email = 'test@example.com';`
- [ ] Пройти полный вход через GitHub и убедиться, что появилась строка в
      `accounts` с `provider = github`.

> Если GitHub-аккаунт использует тот же email, что и Яндекс, вход упадёт с
> `OAuthAccountNotLinked`. Это не баг: Auth.js намеренно не склеивает
> провайдеров по совпадению email. Привязки двух провайдеров к одному
> аккаунту в MVP нет.

### 1.5. Смысловой поиск

Ключ MWS заведён локально, слой работает. Осталось глазами:

- [ ] Открыть `Ctrl+K` в браузере и убедиться, что перехват сочетания клавиш
      работает (Chrome и Firefox вешают на него адресную строку), список
      появляется сразу после ввода и перестраивается через паузу,
      а стрелки и Enter водят по результатам.
- [ ] Не забыть про `MWS_*` в `.env.production` при деплое. Забудешь —
      поломки не будет, поиск просто останется полнотекстовым.

Живой вызов API проверяется отдельным тестом: `tests/embeddings-live.test.ts`.
Он единственный ходит в сеть и стоит денег — правда, доли копейки, — и сам
пропускается без `MWS_API_KEY`, поэтому `npm test` зелёный и без ключа.
Запускать его стоит после смены провайдера, модели или размерности:
остальные тесты работают с подставным векторизатором и не заметят, что
настоящий API отвечает не тем.

Если качество на русском разочарует, план Б — Yandex AI Studio
(`text-search-doc` / `text-search-query`). API у обоих OpenAI-совместимый,
переезд стоит смены `MWS_BASE_URL`, `MWS_EMBEDDING_MODEL`,
`EMBEDDING_DIMENSIONS` (у Яндекса 256 против 1024) и переиндексации.
Мешает только окно: у Яндекса 2048 токенов против 8192, поэтому нарезка
из редкой подстраховки станет основным путём.

### 1.6. Новые фичи — что осталось руками

Основное закрыто браузерными тестами (`npm run e2e`). Мышью и глазами
остаётся то, чего робот не воспроизводит:

- [ ] Перетащить файл в редактор мышью — у drop своя ветка с `posAtCoords`,
      и вставка должна попасть туда, куда бросили, а не под курсор.
- [ ] Открыть заметку со связями и режим ответа на телефоне: обе полосы
      рассчитаны на перенос, но проверены только на широком экране.
- [ ] Убрать `MWS_API_KEY` из `.env` и перезапустить: поиск остаётся
      полнотекстовым, блока «Похожие» нет, пункта «Спросить» нет,
      ничего не падает.

> **`MWS_CHAT_MODEL` — имя деплоя, а не строка из каталога.** В каталоге
> Model Hub модель записана как `qwen3.6-35b-a3b`, а API ждёт
> `qwen3-6-35b-a3b`. На неверном имени приходит `404 DEPLOYMENT_NOT_FOUND`,
> и приложение честно деградирует: поиск работает, ответы молча пропадают.
> Проверить, что видит проект:
>
> ```bash
> curl -s -H "Authorization: Bearer $MWS_API_KEY" "$MWS_BASE_URL/models"
> ```

### 2. Когда появится домен

Это блокирует всё остальное.

- [ ] Направить A-запись домена на сервер.
- [ ] Поставить Docker и compose-плагин на сервер.
- [ ] Зарегистрировать приложение VK ID: <https://id.vk.com/business/go>,
      Redirect URI `https://<домен>/api/auth/callback/vk`.
- [ ] Перевыпустить OAuth-приложения GitHub и Яндекса на боевой домен
      (или добавить второй Redirect URI рядом с localhost).
- [ ] `cp .env.production.example .env.production` и заполнить.
- [ ] **Обязательно заполнить `ALLOWED_EMAILS`.** Пустое значение означает,
      что зарегистрироваться сможет любой, кто нашёл сайт.
- [ ] Развернуть:
      `docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build`
- [ ] Проверить вход через VK — первый живой запуск этого кода.
- [ ] Поставить бэкапы в cron:
      `0 4 * * * /opt/md-note/scripts/backup.sh >> /var/log/md-note-backup.log 2>&1`
- [ ] Проверить восстановление из бэкапа, а не только его создание.
      Файлов теперь два: дамп базы и архив вложений. Восстановить только
      первый — значит получить заметки со сломанными картинками.

### 3. Если VK ID не заработает

Скорее всего проблема будет в `device_id`: VK возвращает его query-параметром
на callback, а требует в теле запроса к токен-эндпоинту. Проброс сделан через
`AsyncLocalStorage` — обёртка в `src/app/api/auth/[...nextauth]/route.ts`
кладёт, `customFetch` в `src/lib/auth/vk-id.ts` забирает.

Что смотреть: логи контейнера `app` во время callback, и приходит ли
`device_id` в query. Auth.js не пробрасывает произвольные параметры callback'а
в token request — если обходной путь сломается, это будет видно именно там.

## Решения, к которым не стоит возвращаться

**Вход по паролю — не делаем.** Credentials-провайдер Auth.js несовместим с
database-сессиями. Подробности и альтернатива — в README, раздел
«Почему нет входа по паролю». Если понадобится вход без Яндекса, VK и
GitHub — это magic link, таблица `verification_tokens` под него уже есть.

**Markdown вместо Tiptap.** Документ писался под ProseMirror и `jsonb`.
Выбрали markdown-исходник в `text`: простые диффы, лёгкий экспорт, поиск
работает по самому тексту. Четыре расхождения со схемой из документа
перечислены в конце README.

**Порядок внутри уровня: сначала папки, потом заметки.** Правило MVP из
документа. Если понадобится произвольный смешанный порядок — это единая
таблица `nodes`, а не костыли поверх текущей схемы.

**Wiki-ссылка кладёт в файл обычную markdown-ссылку, а не `[[uuid]]`.**
Свой синтаксис пришлось бы поддерживать в remark-плагине, в санитизации и
в экспорте, а взамен он дал бы только автоматическую подстановку нового
заголовка при переименовании цели. Адрес и так не ломается — он UUID.
Если однажды станет мешать именно устаревший текст ссылок, дешевле пройтись
по `note_links` разовым скриптом, чем заводить свой формат.

**Ответ на вопрос приходит целиком, а не потоком.** Стриминг ощущается живее,
но заводит второй контракт ошибок рядом с JSON-овским: после первого
отправленного байта честного 500 уже не отдать. Пока хватает индикатора.

**Публичные страницы отдают `robots: noindex`.** Личные заметки, ссылками
делятся адресно. Снимается одной строкой в `generateMetadata` в
`src/app/n/[noteId]/page.tsx` и `src/app/f/[folderId]/page.tsx`.

## Поиск: что отложено сознательно

Не «не успели», а «рано». У каждого пункта записан признак, по которому
станет понятно, что пора.

**Реранкер `bge-reranker-v2-m3`.** У MWS он есть и сейчас бесплатен — в
статусе Preview, то есть без SLA и без обещания, что так останется. Это
cross-encoder: получает пару «запрос + текст» вместе и оценивает
релевантность напрямую, а не сравнивает два независимо посчитанных вектора.
Качество ранжирования у такой схемы заметно выше.

Почему не сейчас: на десятках заметок реранкер переупорядочивал бы top-20 из
корпуса в полсотни — то есть почти всё, что есть. Выигрыш близок к нулю, а
цена — лишний сетевой вызов и +300–800 мс к каждому запросу.

Когда включать: когда заметок станет несколько сотен. Шов оставлен в
`searchNotes` (`src/domain/search.ts`) сразу после слияния RRF — ступень
встаёт между `fuseByRrf` и обрезкой по `SEARCH_LIMIT`. Делать её надо
опциональной, с таймаутом и откатом к порядку RRF при ошибке: Preview-сервис
не должен ронять работающий поиск.

**HNSW-индекс по векторам.** Сейчас векторный поиск — полный перебор, и это
правильно: на тысячах векторов перебор быстрее обхода индекса, а индекс ещё
и приблизительный, то есть меняет выдачу.

Когда включать: когда векторов станут десятки тысяч (примерно от тысячи
заметок) и `explain analyze` на запросе из `findSemanticMatches` покажет
заметное время. Это одна строка в схему:

```sql
create index note_chunks_embedding_idx
  on note_chunks using hnsw (embedding vector_cosine_ops);
```

**Сравнение MWS против Yandex на живых данных.** Выбор MWS сделан по
измеримым признакам — окно 8192 против 2048, цена, наличие реранкера, — но
не по качеству на русском: его никто не мерил. У Яндекса при этом есть
принципиальное преимущество, асимметричная пара `text-search-doc` /
`text-search-query`, обученная отдельно под «короткий запрос» и «длинный
документ».

Когда делать: когда индекс поработает и накопится десяток-другой реальных
запросов, на которых видно, что выдача не идеальна. Час работы: оба API
OpenAI-совместимы, прогнать те же запросы через второго провайдера и
сравнить глазами. Переезд, если он оправдается, — `MWS_BASE_URL`,
`MWS_EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS` (256 против 1024) и
переиндексация; помешает только окно 2048, из-за которого нарезка станет
основным путём вместо редкой подстраховки.

## За чем следить дальше

- **Rate limiting живёт в памяти процесса** (`src/lib/rate-limit.ts`).
  Инстанс один, этого достаточно. Появится второй — менять на Redis;
  сигнатура `consume()` останется прежней.
- **Ребалансировка позиций** срабатывает, когда зазор между соседями меньше
  `1e-6` (`src/domain/move.ts`). Тест на это есть. Если после сотен
  перетаскиваний порядок начнёт «залипать» — смотреть туда.
- **Заметки в корне не видны по ссылке на папку.** Ожидаемое поведение из
  документа: они не входят в поддерево конкретной папки.
- **Лимиты** заданы в `src/lib/validation.ts`: 200 символов заголовок,
  512 КБ на заметку, 5000 заметок и 1000 папок на пользователя, 10 МБ на
  вложение и 2000 вложений на пользователя. Число для вложений обязано быть
  согласовано с `client_max_body_size` в `deploy/md-note-proxy.conf`: если
  nginx окажется строже, он отрежет запрос раньше нас, и человек увидит
  его страницу ошибки вместо нашего сообщения.
- **Осиротевшие вложения никто не убирает.** Удалили `![…]()` из текста —
  файл остался на диске и строка в базе тоже. Сборки мусора нет намеренно:
  «ссылки в тексте больше нет» и «файл не нужен» — разные утверждения,
  та же картинка может быть вставлена в другую заметку или вернуться
  отменой правки. Появится признак того, что место кончается, — считать
  ссылки по всем заметкам владельца и удалять непривязанные старше недели.
- **Связи пересчитываются на каждом сохранении текста**, то есть каждые
  800 мс при активной правке (`updateNote` в `src/domain/notes.ts`). Это
  разбор markdown без рендера, порядка миллисекунды на обычной заметке.
  Если сохранение начнёт тормозить на больших заметках — смотреть сюда.
- **Панель связей запрашивается один раз при открытии заметки** и не
  обновляется на правках. Бэклинки от правки этой заметки и не меняются;
  похожие меняются, но перезапрашивать векторный поиск на каждое нажатие
  клавиши незачем.

## Как вернуться к рабочему окружению

```bash
npm install
npm run db:up          # Postgres в Docker
npm run db:migrate     # схема, индексы, триггеры
npm run dev
```

`.env` уже заполнен и лежит вне git: там `AUTH_SECRET`, `DATABASE_URL` и
ключи OAuth-приложений GitHub и Яндекса, зарегистрированных на
`http://localhost:3000`. Если файл потеряется — шаблон в `.env.example`,
приложения перерегистрировать заново.

Перед коммитом: `npm run typecheck && npm run lint && npm test`.
Браузерные — отдельно, они поднимают dev-сервер: `npm run e2e`.
Один из них ходит в живую модель и стоит доли копейки; без `MWS_CHAT_MODEL`
он сам пропускается.
